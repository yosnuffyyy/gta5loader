ACTUAL SHADER AND REFERENCE BEHAVIOR
The original recovered PS996bb42f448956f2 has one t14 comparison call:
textureSampleCompareLevel(t14,s14,direction,reference).
Binding46/t14 is a depth cube. Binding30/s14 is a comparison sampler.
The same sampler is shared by t24,t25,t26,t27,t28,t29,t30, so changing that
sampler to Always would also disable comparisons for other valid lights.
The shader's explicit no-shadow branch sets visibility r9.z=1.0 and then
multiplies lighting by that visibility. This is independently distinguishable
from merely supplying black or zero-depth data. The cube reference is a
length multiplied by CB6[17].w; no clamp to[0,1] appears before the sample.
The captured count1/selector2 state permits the sample. Its active sampler
descriptor, complete transforms and intended selected resource remain
missing from the supplied phone evidence.

The preserved reference worker returns null for an undersized cube view.
Its caller supplies a newly created1x1x6 depth32float cube, with no explicit
upload/clear in dummyTexture. This uses WebGPU zero-initialization. A valid
original comparison sampler is preserved; dummySampler Always is selected
only when a compatible real comparison sampler is absent. Therefore the
reference's empty cube is NOT a universal neutral-shadow operation.

SAFE IMPLEMENTATION GATE
A production option is deferred because the specific resource's intent and
the active sampler/reference domain have not been established. An optional
switch must not turn a genuinely broken shadow-map selection into an
unreported no-shadow image. A future validated path should:
1. Identify the engine placeholder by verified provenance and generation,
   not only transient handles708/709, dimensions or8 zero bytes.
2. Match the exact shader/binding contract and original descriptor, and
   prove neutral visibility for the real comparison and reference domain.
   Do not replace the shared s14 comparison function globally.
3. Lazily allocate a separate single-mip, six-layer Depth32Float cube,
   initialize ALL faces explicitly, and bind only for the eligible case.
   Keep the original source/view/data intact. Valid shadow maps use their
   original path. Other mismatches continue to fail strict validation.
4. Order initialization before dependent draws on the same GPU stream;
   retain the cube and view through submitted work. No per-draw CPU wait.
5. Keep strict mode as the default and log bounded activation counts with
   provenance. Freeze the option per run or include it in every affected
   view/bind-group cache key; invalidate on mutation/replacement/generation.
6. Re-run original-pair, mixed-light, dynamic-constant, resource-lifetime,
   invalid-binding and Metal pixel tests before producing a candidate IPA.
