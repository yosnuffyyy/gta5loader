UAV BINDING AND ORDERING
0.16 gives APPEND/COUNTER UAV views independent hidden counters. A supplied
count resets those counters; UINT_MAX preserves their contents. Counts on
null/non-counter views have no effect as defined by D3D11, and are counted
and logged. The renderer records resets in the shared GPU command order.
A reusable 4 KiB staging buffer gives each reset a unique word until submit;
staging reuse follows submission. COPY_COUNTER copies the current GPU value
into a checked DWORD-aligned destination. No new per-reset GPU wait.

FOLLOW-ON OPERATIONS
The browser command path predicts storage bindings, DISPATCH, CLEAR_UAV,
COPY_COUNTER and GENERATE_MIPS adjacent to this blocker. They are implemented
and covered together rather than returning fabricated success:
- Exact read-only/writable storage-buffer view ranges; unaligned starts use
  cached GPU copy-in/copy-out proxies instead of CPU readbacks. The per-view
  proxy ceiling is 64 MiB, total 128 MiB, allocated only when needed.
- Storage texture mip/layer views and cached shader format variants. Each
  program keeps at most eight variants with LRU replacement; original game
  shader files stay unchanged. Draw pipeline keys include storage formats.
- Actual compute dispatch with checked workgroup limits and cached pipelines.
- Raw/structured and supported typed UAV clears, buffer zero clears, and
  bounded texture clear chunks. Temporary nonzero texture chunks <=256 KiB;
  cached zero source <=1 MiB. Counter resets remain separate from data clear.
- GPU linear mip generation for supported float, renderable 2D SRV ranges,
  with cached pipelines and mip/layer views/groups released with resources.
- Signed/unsigned integer texture mappings and raw readback widths needed by
  these bindings. Read-only attachments/storage reads do not falsely dirty
  source proxies; actual writes still invalidate them.
