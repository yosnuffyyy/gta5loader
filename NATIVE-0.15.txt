NATIVE 0.15 — GPU DEPTH/STENCIL/FLOAT SRV PROXIES

Physical0.14 reached Prologue1/CUTSCENEINTRO and initialized its animated
camera. It executed98,193 commands,7,793 draws and851 presentations before
the unimplemented depth-as-color adapter stopped DRAW. The prior vertex
guard was absent. These counts do not verify correct successive3D frames.

D3D depth views can be read as float textures; the original browser WGSL
uses that ABI. WebGPU requires compatible texture sample types. Native0.15
ports all three browser adapters: depth toR32Float,stencil toR8Uint,and
float toDepth32Float for comparison sampling. Each source owns its proxies.
The renderer lazily allocates views/groups for requested mip/layer ranges,
refreshing them only when the source version changes. Draws,clears,uploads,
region/resource copies and resolves invalidate source contents. Read-only
depth/stencil attachments do not dirty the source.

Conversions are render passes in the same encoder as the consuming game
draw. No CPU depth pixel copy,readback or new per-draw completion wait.
Unchanged sources reuse textures,views and groups. Three conversion
pipelines are cached. Ordinary shaders cache the absence of proxy bindings.
Nominal proxy texel storage is capped to256MiB across the device;this is a
ceiling,not a preallocation or measured physical footprint. Source destroy
releases associated passes and textures. Counters expose actual proxy
allocations,refreshes,reuse,nominal peak storage and remaining live objects.
Multisampled proxies remain explicitly unsupported with texture/DXGI/SRV
details;unsupported operations do not silently return success.
