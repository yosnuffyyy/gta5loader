EXACT CHANGES
Pipeline key:retain only elements matched by semantic/index in the original
vertex input signature. Use the existing signature scan to calculate used
slots and filter the key in one pass. Keep consumed formats, offsets, slots,
classes, step rates, ordering and invalid descriptors for strict validation.
Original input layouts, shader reflection and pipeline creation are unchanged.
Only redundant key distinctions disappear. No speculative async compilation,
prewarming, larger cache, new shader code or quality change.

Uniform packing:each live shader program remembers only its most recent
immutable slice in the current draw batch. Compare all source bytes and
implicit zero fill against that slice. Equality permits the same dynamic
offset; changed/null/offset/rebound state is rechecked and gets a new pack
when required. The immutable snapshot records copied prefix lengths, so stable missing banks
do not trigger repeated zero-tail scans. Cache identity includes the batch
serial; never reuse data
after mirror/slot recycling. Constants are not deduplicated using handles,
float equality, hashes or assumed unchanged resource revisions. Packing and
GPU submission ordering remain unchanged. No GPU-writable buffer upload or
texture data is guessed redundant or discarded. No extra GPU buffer or wait.

Diagnostics:report immutable pack/reuse counts and actual GPU uniform-upload
bytes separately from protocol buffer/texture upload command counts. Report
queue submits, draw batches, byte-edge and whole-copy submissions using
existing bounded counters. Categories overlap; they must not be added.
Preserve worst pipeline shader/key/cost records, display timestamps, frame
quantiles, CPU service/handler/upload waits, user scene marker, process memory,
engine heap, script/worker state and input event-to-hook metrics.
