STAGE 7 — HIGHER QUALITY WITH MEASURED HEADROOM
- Compare identical routes before/after changes: median and slow frame times,

  textures, draw distance and effects one setting at a time.
- Reduce redundant state/pipeline work, copies and CPU/GPU waits where profiles
  identify them. Consider adaptive resolution only for demonstrated GPU load;
  it will not solve a CPU or engine-heap bottleneck.
- Keep a tested conservative preset and rollback after regressions.
Gate: visible improvements with sustained measured performance and a stable
fallback. No maximum-settings promise or assumed universal iOS memory budget.

HOW TO FINISH FASTER WITHOUT REWORK
- Concentrate on the Prologue path. Defer networking, unrelated optional host
  services, broad controller models, cosmetic UI work and high settings.
- Reuse verified compiler/engine work and independent reference code. Avoid
  speculative engine rewrites or binary patches.
- Reuse content-verified CI objects. During iteration test affected subsystems;
  before delivery run the relevant full regression gate and IPA audit.
- Keep diagnostics automated inside development builds. Request phone tests at
  architecture/visual/playable milestones, or for device-specific evidence,
  instead of shipping an IPA for each tiny implementation step.
- Use representative command/asset fixtures where practical to reproduce bugs
  cheaply. Fixtures and Mac runs never replace physical iPhone validation.
- Apply memory discipline from the start; tune performance using actual game
  workloads. A successful diagnostic does not prove a gameplay memory budget.
- No reliable completion date yet. Re-estimate after renderer feasibility and
  the first actual game frame; these expose the largest remaining unknowns.
