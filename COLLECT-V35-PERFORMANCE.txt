Collect 60 seconds of stable gameplay plus a shorter troublesome transition:

- Preserve the trace and matched raw app report; do not upload game archives.

3. WHAT TO CALCULATE
Use only comparable counts from one aligned phase. Displayed intervals are
not simulation frames. Wrapper queue submits are not frames or all internal
backend transfers. Handler/upload/pipeline/map/completion walls overlap.
Counter deltas can describe a phase only with both boundary snapshots.
Do not sum p95s, average process quantiles or infer GPU saturation from a wait.
Do not divide uniformGPUbytes by protocoluploadcount as copy amplification.

4. CURRENT MISSING METRICS
True engine-frame CPU intervals; actual GPU duration/counters; native opcode
exclusiveCPU partition; per-cause flush/transfer bytes; input p95/p99; archive
queue delay; phase-specific pipeline key recurrence and driver allocations.
CPU protocol timestamps are sampled before flush and published after completion;
they are not GPU hardware timestamps. See PERFORMANCE-AUDIT.md sectionsB/L.

5. ACCEPTANCE FOR ANY LATER OPTIMIZATION
Compare the same phase/settings/device state across repeated runs, separate
cold compilation from warm gameplay, retain pixels/data/query/input tests,
and record actual displayed p50/p95/p99 plus memory/input changes. Do not call
an O0 Paravirtual fixture a measured A18 Pro FPS gain. Keep original working IPA.
