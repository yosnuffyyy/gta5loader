### Memory and performance limits

No before/after physical process-footprint, thermal, displayed-frame percentile or input-to-display measurement is available for0.37. The new callback pool is fixed128 entries (6,144 bytes on the host64-bit layout); cache metadata adds24 bytes per256 entries (6,144 bytes); the recovery ring adds24,640 bytes plus bounded writer snapshots. Opaque driver allocations are excluded. Autorelease lifetime is bounded by each service drain/poll, but no specific MiB saving or original leak is proven. The pressure policy may retain128 additional hot driver pipelines compared with0.36. This must be checked against actual headroom, not marketed as a memory reduction.

The original submission/uniform optimizations remain and pass their same byte/pixel tests. Their existing improvements are not counted as new0.37 work. The new event path removes synchronous END waits, not the original draw submission boundary. Pool-pressure/cancellation logic is present; the real GPU replay did not saturate all128 slots, so physical backlog behavior remains a test target.


Physical0.37 gameplay, memory stability, FPS and end-to-end input latency remain unverified. Audio output unfinished. No roadmap-stage advancement.
