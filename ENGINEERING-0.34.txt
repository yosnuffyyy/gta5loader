CONFIRMED SRV ROOT CAUSE
Native 0.33's optional reference-shadow policy admitted only the Four-light
PS 996bb42f448956f2. The new failing PS 6e9619cde3dac275 is the Eight-light
PS_PedTextured_Eight in ped_alpha. Its t14 comparison block, sampler ABI and
first selector guards match Four, but the hash whitelist rejected it.
The 32-region guard parser also filled with Eight's float guards before
collecting its integer light-count guards. Both are compatibility-classifier
coverage bugs. Source 708's captured creation/upload is genuinely a one-layer
4x4 BC1 texture, not a six-face texture with omitted uploads.

The actual phone-side forward-light/cache record's intent remains unverified.
This does not establish an original engine producer bug or prove that the
resource was intentionally selected as a no-shadow state in the PC engine.

CORRECT OPTIONAL REFERENCE CONTRACT
The policy now certifies sampling semantics rather than shader/resource IDs:
one direct textureSampleCompareLevel use of a declared depth cube; the actual
comparison sampler and ABI slot; paired 0/3 selector guards; current selector
2.0; and the exact captured descriptor, zero BC1 upload, version and ordinary
sampler contract. The existing recovered/native sampler-class adapter selects
comparison Always for that ordinary-to-comparison mismatch. Its result is 1
independently of valid cube depth values. A cached 1x1x6 Depth32Float cube is
initialized before dependent draws in the same encoder, preserving that
reference result. Original 2D data, shader code, material and draw remain.

No hash whitelist, count-one restriction, geometry omission or generic SRV
validation bypass remains in this policy. Valid real cubemaps use their normal
path. Changed content/versions, ambiguous selectors, genuine comparison
samplers and unknown contracts retain strict errors. Strict mode is available
by leaving the optional setting off. No additional last-resort sample removal
was needed or added for unknown active bindings.

Reflection is bounded to 64 regions and conservative integer thresholds 0..7.
Inactive proofs still evaluate fresh packed bytes on every relevant draw.
Reference flags are synchronized into cached variants by sorted ABI binding,
including bindings above 63; bind-group identity retains flags and resource
generations. One cube per GPU service, 24 logical bytes excluding driver
allocation/residency, as in 0.33. No new per-draw GPU completion wait.
First activation per program binding reports shader, sampler slot, SRV/source
and generations; total uses and the bounded transition/fatal context remain.
Fatal CB captures now use reflected block sizes, capped at 944 + 752 bytes.

NATIVE UI
Main: dark dashboard, clear Start Game, selected folder/access status, native
version/runtime status and Settings, Controls, Files and Diagnostics routes.
Full raw logs and experimental settings live in Advanced.
Graphics: fullscreen, fixed 640x360, optional displayed-frame diagnostics and
visible-scene marker. Unsupported graphics controls are not invented.
Controls: existing DualSense bridge, deadzone, camera sensitivity, touch opacity
and joystick size. Button remapping is explicitly unavailable.
Files: native folder picker, persistent bookmark, honest three-prefix sample
check, visible checking/fatal status and disabled change button while busy.
Advanced: optional shadow mode, runtime checks, bounded full report, copy/export
and confirmed restore defaults. Files and folder selection are preserved.

Preferences are persistent. Fullscreen keeps the whole aspect-fit image,
uses public status-bar/home-indicator preferences and keeps Settings/Stop
reachable. No rounded mask crops the game viewport. Native pages support
safe areas, scrolling, labels, minimum action targets and Dynamic Type.
The test caught and fixed a Files-label ownership bug: attach the strong local
label to its parent before keeping a weak observation reference.

Controller/touch reduction and engine hook are unchanged. Opening settings
releases held input. Closing resumes input only after dismissal and while the
app is active. Drift/reconnect behavior, hidden non-interactive touch art and
deliberate touch wake are preserved. Backgrounding still stops the session;
it does not promise background gameplay or seamless engine resumption.

The report has an independent bounded text model. UIKit text is updated only
while Advanced is visible; opening it synchronizes the real full text.
The FPS label reuses the existing five-second timer and actual drawable
timestamps. There is no new display-link timer, controller polling loop,
per-frame view reconstruction or GPU synchronization for the UI.

PERFORMANCE EVIDENCE
No new physical-device performance measurements are available. The supplied
Native 0.33 evidence identifies three important costs: upload/ordered-flush
handling (frequently over 60 ms per PRESENT), pipeline compilation spikes,
and render-queue backpressure delaying simulation/input. Their nested times
overlap and must not be added as independent CPU/GPU costs.

New UI-only fixture: 200 distinct approximately 8 KiB text assignments took
470.392 ms through UITextView versus 0.018 ms through hidden report storage.
The deterministic result is 200/200 UIKit text assignments avoided while
hidden, with exact final text synchronized when shown. This is one simulator
API-wall workload with fixed ordering, not GPU time, frame pacing or phone FPS.

Previously implemented optimizations remain independently checked:
same-batch uniform packs 192 -> 18, uniform GPU bytes 49,152 -> 4,608;
unused-layout pipeline creates 32 -> 1; ordered-readback pressure waits 6 -> 0
and explicit completions 7 -> 1 in their isolated golden-output fixtures.
These are preserved 0.31/0.32 changes, not new 0.34 FPS improvements.
The 192-key working-set fixture still has 192 creations, 384 hits and zero
evictions at capacity 256. The pressure mode remains bounded to 128.
One 64 KiB archive buffer and at most eight descriptors are unchanged.
No new phone process-memory measurement or true GPU timestamp measurement.

REMAINING DEVICE CHECKS
Install using the existing signing/sideload setup. Select the existing web
folder once; the new bookmark should restore it on subsequent launches.
In Settings > Advanced, enable Reference shadow compatibility before Start.
Strict mode intentionally retains invalid active placeholder failures.
Use 640x360. Test the new PS pass, characters/materials and real shadow changes
through the security guard and vault. Look for uninterrupted correct animation
and camera frames, then test sustained foreground play beyond 180 seconds
toward 10–20 minutes. Test DualSense/touch handoff, simultaneous actions,
Settings dismissal, fullscreen/safe areas, cancellation and clean Stop.
Mark the visible scene for comparable display intervals and export Advanced
diagnostics, including the first fatal context if any. Counts alone are not
proof of correct rendering. Unknown future graphics operations, 111 untranslated
hull/domain/geometry records, metadata/asset diagnostics and audio remain risks.

see AUDIO-INVESTIGATION-0.33.txt. No synthetic audio or fabricated assets added.
