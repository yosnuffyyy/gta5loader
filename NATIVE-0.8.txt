0.8 implements the native shared-ring DRAW handler and a local shader loader.
It reads the selected web folder's shader index and just the requested range
from a shader pack, or the individual WGSL/constant files as a fallback.
Runtime shader reads use no network or whole-pack cache. Traversal and
symbolic links are rejected; index/source/table lengths are bounded.
Packed constants follow the browser translator ABI. Native shader modules,
samplers, texture views and binding groups are reused. The draw path supports
direct/indexed/instanced and basic indirect commands, vertex semantics and
buffer offsets, common color/depth/blend/raster state, scissor and viewport.

Draws sharing targets remain in the same render pass. Constants occupy three
fixed 512 KiB GPU slots and one 512 KiB CPU mirror (2 MiB total). Slots are
reused only after GPU completion. Pipeline cache holds at most 128 entries.
GPU uploads, copies, destruction, readback and presentation first submit
pending draws to preserve resource ordering. Constant-only shadow updates
keep the pass open: each draw already owns its constant snapshot. The replay
checks different constants on the left/right halves of one image. No
per-draw CPU/GPU completion wait.

The diagnostic replay uses the exact original shader pair from the phone
trace through the production DRAW handler. It compares every pixel for ten
16x16 offscreen cases: starts/base vertex, direct/indexed/instanced/indirect
commands, constants and first-constant offset, blending, scissor, depth
rejection and depth pass. Eleven draws reuse four native pipelines. The BC
and original queue checks remain. These fixtures do not prove game rendering.

Pending operations fail explicitly with their first error. Storage bindings,

inter-stage location remapping, indirect built-in ID rebasing, compute and

Sampler border addressing, mirror-once and mip bias retain the existing
