STATFS / STATVFS
The unchanged engine's statvfs (90925) requests a 120-byte syscall result,
then converts it to a 112-byte libc struct. Native Apple structs differ.
The host queries fstatvfs against rooted file descriptors and serializes all
fields/padding explicitly. Total/free/available blocks remain 64-bit; the
allocation fragment size is kept separately from optimal I/O block size.
No fictional free-space value or capacity cache is used.
Virtual root/cwd and userdata report the app save volume. Selected data paths
report the granted game volume and retain read-only flags. Missing files,
symlinks, traversal, unknown paths, bad sizes and invalid buffers fail without
writing the output. Temporary descriptors close before returning.
Worker proxy 28 uses the original typed argument format and signed errno.
No additional thread, heap cache or engine instruction patch is required.

ENTROPY
The engine's _InitRng reads 52 bytes from /dev/urandom, then /dev/random as a
fallback. The old root resolver rejected both, explaining InitRng -199.
Only those exact virtual names now open the OS /dev/urandom read-only; all
other OS paths and device writes remain rejected. The existing bounded
reader serves the seed. No deterministic/random-test values seed the game.
The engine's original wc_InitRng health test, GenerateBlock and FreeRng are
called in the runtime regression. Names/signatures are pinned to this engine.
This does not add multiplayer, Social Club, Bink video decoding or gameplay.
Those diagnostics are retained; their absence in future phone runs is not
claimed before the physical test.
