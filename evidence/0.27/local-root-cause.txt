WHY THE ENGINE SELECTS THIS RESOURCE IS STILL UNRESOLVED
Existing read-only disassembly of44278 CLightGroup::SetForwardLights shows:
  44528 GetLightShadowIndex selects a cached light record.
  The record's type is converted to float in the shadow matrix's w lane.
  Texture-array entries are then sent through9881 grcEffect::SetGlobalVar.
  The no-shadow branch zeroes those constants and sets default textures.
44279 delegates to44278. Function9881 stores the supplied pointer into the
global table; it does not manufacture layers. CreateBaseMaps43801 prepares
the arrays and a separate default texture. These paths were already traced
in0.24 and were reviewed again; they are not a newly discovered fix.
The supplied command stream contains the resulting GPU handles, not the
producing light/cache entry or its selected engine texture pointer. Static
inspection does not identify which selection/default/stale global led to708.
No binary patch, arbitrary substitute cube, type reinterpretation, render
skip or extra inactivity proof is justified by the available evidence.

Additional read-only quality investigation: the existing native arguments
inherit -shadowQuality=-1 from the reference browser's low profile. In
GetShadowRes43800, the settings field at offset40 selects resolution2 for
