P2: QUEUE-ORDERED UNIFORM REUSE
Previously every third flushed batch waited for all submitted GPU work
because the three-slot uniform ring wrapped. Queue writes copy CPU bytes
and are ordered before their associated next submission and after earlier
submissions. Reusing the slot therefore does not itself need a CPU wait.
Reuse is now bounded to 16 submitted batches or 4 MiB of pending uniform
payload. A preflight bound prevents a batch from exceeding that payload cap.
Explicit fences, required readbacks and query result dependencies remain.
Three 512 KiB GPU uniform buffers and the existing CPU mirror are unchanged.
The payload cap is not a measurement or bound of all driver/GPU memory.

Ordering regression: 96 changing-constant batches (four alternating patterns),
32 slot wraps, all 256 pixels and exactly 96 query samples, both policies twice.
Completion calls fall from 33 to 7 in this fixture; no stale data accepted.
  bounded queue reuse: 7 completion waits, 68.184 ms CPU wait, 6 uniform-pressure waits.
  0.23 reference: 33 completion waits, 404.294 ms CPU wait, 0 uniform-pressure waits.
  bounded queue reuse: 7 completion waits, 61.483 ms CPU wait, 6 uniform-pressure waits.
  0.23 reference: 33 completion waits, 313.636 ms CPU wait, 0 uniform-pressure waits.
Four-page query pool remains bounded. Greater concurrency can exercise its
legitimate backpressure path. The original fixture's zero-wait assumption
was replaced by exact results, all maps completed, bounded memory, stale-ID
suppression and shutdown checks, under both policies (180 cases each):
  bounded queue reuse: 12/12 completed maps; 2 query-pool waits, 44.678 ms.
  0.23 reference: 12/12 completed maps; 0 query-pool waits, 0 ms.
  bounded queue reuse: 12/12 completed maps; 3 query-pool waits, 58.092 ms.
