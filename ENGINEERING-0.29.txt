ENGINE BRIDGE
The pinned original engine already calls wasm_input_publish_js(-1-pointer)
after its ioPad debug/update passes and before CPad consumers, and at the
CControl update tail. Native 0.28 returned without injecting input there.
Native 0.29 handles the verified pad pointer 12840656 and three verified
control objects 24488864,24660320,24831776. Other CControl instances retain
original engine state, matching the reference whitelist behavior.
UI/controller threads never write engine RAM. The engine thread snapshots
a fixed native buffer at its existing synchronous hook, writes current
button/axis/trigger/connection fields, and leaves original button history
to the engine. It selects pad-source prompts for this virtual/physical pad.
No engine instructions, game action definitions or mission scripts change.

INPUT IMPLEMENTATION
GameController extended-profile events run on the main queue. Discovery is
restricted to initial setup and connection notifications. The profile's
handler reads sticks, independent triggers, four face buttons, shoulders,
stick clicks, D-pad, Menu and optional secondary Menu into one fixed state.
Buttons use the original ioPad enums; contextual actions come from the
engine's loaded game controls. See INPUT-CONTROLS-0.29.txt for the exact map.

The touch overlay has two analog sticks and matching pad buttons, including
Pause/View and D-pad. Ten fixed touch slots support simultaneous move/look/
aim/fire. Button ownership is combined without duplicate release; stick
ownership is exclusive until release/cancel. Rendering labels and colors
are allocated once, not rebuilt on every controller event.

A centralized mutex-protected source machine implements touch/controller
handoff. Meaningful fresh controller activity hides art immediately at alpha
0; art never intercepts touches. The game container receives the wake touch
and applies that same initial gesture. Reconnect/resume/start baseline
snapshots quarantine held input. Drift is filtered with configurable stick
deadzone and takeover hysteresis. Held inputs reconcile through neutral
state; unrelated physical disconnects preserve an active touch hold.
Disconnect is processed before refreshing controller discovery, including
rapid reconnect when the framework reuses the same controller object.

A 64-snapshot queue retains digital press/release edges across engine ticks;
analog updates coalesce without erasing those edges. Overflow is bounded,
counted and safely reconciles through release, rather than claiming lossless
delivery. There are no input polling loops, graphics waits or allocations in
the C hot path. App interruption clears input; entering background requests
the existing native shutdown rather than running the GPU in background.

FULLSCREEN / SETTINGS
Persisted public UIKit fullscreen preference, landscape request, status bar
hiding, home-indicator auto-hide request and bottom-edge gesture deferral.
Same game surface and Metal layer; fixed640x360, aspect-fit16:9, no crop or
stretch. The embedded viewport is also height-bounded for landscape use.
Safe-area controls recompute and release touches on resize. Settings remains
accessible for exit/fullscreen, scene marker, Stop and Resume. Four persisted
sliders configure noise deadzone, camera sensitivity, stick size and opacity.
The engine's own pad conversion/deadzone is retained.

PERFORMANCE / LIMITATIONS
No device input latency or FPS improvement is claimed. The C microbenchmark
is not end-to-end latency. Runtime reports event-to-hook state age and queue
pressure/overflow; those counters do not prove that the character moved.
No true GPU timing or new renderer optimization is introduced.
Physical DualSense mapping in gameplay, touch gestures, menu/context actions,
fullscreen safe areas/home indicator, OS27 behavior and sustained animation
still require the iPhone. Haptics/adaptive triggers/motion/touchpad gestures,
keyboard input and native audio output are outside this controls change.
The game's runtime contextual mappings remain authoritative.
